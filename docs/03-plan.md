# 03. 진행 순서

> 원칙: **순서대로 진행하고, 단계가 끝날 때마다 "보여줄 수 있는 것"이 하나 있어야 한다.** 속도는 상황에 맞추고, 막히면 범위를 줄인다.
> 3단계까지만 돼도 "브라우저에서 웹캠으로 로봇 가르치기"는 완성이다.

## 1단계 — 각각 따로 동작시키기

**목표:** 로봇과 손이 각자 화면에 나온다.

- [ ] dev-server-01 환경 확인(GPU, 포트) → 05-server-setup.md
- [ ] MuJoCo에 SO-101 + 바닥 + 블록 + 목표 표시 장면 만들기 (`sim/scene.xml`)
- [ ] 화면 없이 렌더링해서 이미지 파일로 저장
- [ ] 관절 값을 코드로 바꿔서 팔이 움직이는지 확인
- [ ] 브라우저(React + Vite)에서 웹캠 켜고 MediaPipe Hand Landmarker로 손 21개 점 그리기
- [ ] 손목 위치, 엄지-검지 거리(집기), 손바닥 펴짐 여부를 화면에 숫자로 표시

**완료 기준:** 렌더링 이미지 1장 + 브라우저에서 손 점과 숫자가 움직이는 화면 녹화

## 2단계 — 손으로 로봇 움직이기 (가장 중요)

**목표:** 내 손을 움직이면 브라우저 속 로봇팔이 따라온다.

- [ ] 브라우저 → 서버 WebSocket으로 손 정보 30Hz 전송
- [ ] 손 좌표(화면 기준) → 로봇 작업 공간 좌표(미터) 변환
- [ ] 떨림 줄이기 필터(One Euro Filter)
- [ ] mink로 목표 위치 → 관절 각도
- [ ] 집기 거리 → 그리퍼 열고 닫기
- [ ] 서버가 렌더링한 화면을 브라우저로 전송(JPEG)
- [ ] 지연 시간 측정(손 움직임 → 화면 반영)

**완료 기준:** 손으로 블록을 집어 목표에 놓는 영상. 10번 중 몇 번 성공하는지 기록.

## 3단계 — 시연 녹화와 1차 학습

**목표:** 로봇이 내 시연만 보고 혼자 블록을 옮긴다.

- [ ] 녹화 시작/끝, 성공/실패 표시 버튼
- [ ] LeRobot 데이터셋 형식으로 저장 (04-architecture.md)
- [ ] 블록·목표 위치는 정해진 목록(시드)에서 무작위
- [ ] 시연 20~30개 녹화
- [ ] ACT 학습 → 정책 1호
- [ ] 평가 스크립트: 고정된 평가 배치 50~100개에서 성공률

**완료 기준:** 정책 1호의 성공률 숫자 + 혼자 옮기는 영상. **이 시점에서 발표 가능한 최소 결과 확보.**

## 4단계 — 손으로 바로잡기

**목표:** 로봇이 혼자 하다 틀리면 손바닥을 보여 넘겨받고, 고친 뒤 돌려준다.

- [ ] 브라우저에서 정책 실행 모드(AUTO)
- [ ] 손바닥 제스처로 HUMAN 모드 전환, 손 내리면 AUTO 복귀 (04-architecture.md 상태 그림)
- [ ] 넘겨받을 때 로봇이 튀지 않게: 손의 움직인 양만 적용
- [ ] 교정 구간 표시(`is_intervention`)해서 저장
- [ ] 2차 학습(시연 + 교정) → 정책 2호

**완료 기준:** 교정 장면 영상 + 정책 2호 성공률

## 5단계 — 비교 실험과 발표

- [ ] 06-experiment.md 비교 실험 (같은 시간: 추가 시연 vs 교정)
- [ ] 결과 표와 그래프
- [ ] 발표 자료, 2분 스토리(01-story.md), 시연 영상 백업(라이브 실패 대비)
- [ ] README 실행 방법 정리

## 막혔을 때 줄일 순서

1. 비교 실험 반복 횟수(시드) 줄이기
2. 교정 기능을 "버튼으로 넘겨받기"로 단순화 (제스처 대신)
3. 렌더링 화면 해상도·프레임 낮추기
4. 4단계 전체를 "향후 계획"으로 돌리고 3단계 결과로 발표
