# 04. 구조

## 전체

```
┌──────────── 브라우저 (내 노트북) ────────────┐
│ 웹캠 → MediaPipe Hand Landmarker (JS)         │
│   → hand 메시지 30Hz ──────────────┐          │
│ 시뮬레이션 화면 <img> ◀── JPEG ────┼──┐       │
│ 버튼: 녹화 / 성공·실패 / AUTO 실행  │  │       │
└────────────────────────────────────┼──┼───────┘
                    WebSocket (Private 포트 전달)
┌───────────────── 서버 (dev-server-01) ────────┐
│ FastAPI WebSocket                              │
│   → 매핑(화면 좌표 → 작업 공간, 필터)          │
│   → 모드 관리(HUMAN / AUTO)                    │
│   → mink 역기구학 → MuJoCo step               │
│   → 오프스크린 렌더 → JPEG 전송               │
│   → 기록기 → LeRobot 데이터셋                  │
│ AUTO 모드: ACT 정책이 행동 결정               │
└────────────────────────────────────────────────┘
```

시뮬레이션을 서버에서 돌리는 이유: 물리 계산과 학습된 정책 실행은 파이썬(MuJoCo, PyTorch)이 표준이다. 브라우저는 입력(손)과 출력(화면)만 맡는다.


## 메시지 형식

브라우저 → 서버 (`hand`, 30Hz):

```json
{
  "type": "hand",
  "t": 1729570000.123,
  "detected": true,
  "wrist": [0.52, 0.61, -0.03],
  "index_tip": [0.55, 0.48, -0.05],
  "thumb_tip": [0.50, 0.50, -0.04],
  "pinch": 0.04,
  "palm_open": false,
  "hand_scale": 0.18
}
```

- 좌표는 MediaPipe 정규화 좌표(화면 0~1). 변환은 서버에서 한다.
- `hand_scale`: 손 크기(손목~중지 뿌리 거리). 깊이(앞뒤) 추정에 쓴다.

서버 → 브라우저: JPEG 프레임(바이너리) + 상태 메시지 `{ "type": "state", "mode": "HUMAN", "recording": true, "episode": 12 }`

## 손 → 로봇 매핑

1. 화면 x, y → 로봇 작업 공간 좌우·위아래 (책상 위 사각형으로 크기 제한)
2. `hand_scale` → 앞뒤 (손이 커지면 가까이). 웹캠의 가장 큰 오차 원인이므로 처음에는 범위를 좁게
3. One Euro Filter로 떨림 제거 (빠르게 움직일 땐 덜, 멈춰 있을 땐 많이 거름)
4. mink로 목표 위치 → 관절 각도. 손목 회전은 처음엔 고정(블록 집기에는 위에서 내려 잡는 자세면 충분)
5. `pinch`가 기준보다 작으면 그리퍼 닫기 (열고 닫는 기준을 다르게 해서 깜빡임 방지)

## 모드 (손으로 바로잡기)

```
           손바닥 0.3초 이상 보임
   AUTO ───────────────────────────▶ HUMAN
 (정책이 조종)                     (내 손이 조종)
     ▲                                   │
     └───────────────────────────────────┘
          손이 0.5초 이상 화면에서 사라짐
```

- **넘겨받는 순간:** 그 시점의 로봇 끝 위치(P0)와 손 위치(H0)를 기억. 이후 목표 = P0 + (현재 손 − H0). 마우스를 들었다 놓아도 커서가 안 튀는 것과 같은 원리(클러치).
- **녹화:** 일반 시연은 `source = "demo"`. 교정 에피소드는 `source = "correction"`으로 전 구간을 저장하되, HUMAN 구간만 `is_intervention = true`.
- **학습에 쓰는 것:** 시연 전체 + 교정 에피소드의 HUMAN 구간 (HG-DAgger 방식). AUTO 구간은 학습에서 빼거나 비교 실험으로 확인.
- 판정 시간(0.3초, 0.5초)은 `config.py`에서 조정.

## 데이터셋

LeRobot 데이터셋 형식. 정확한 필드 이름과 저장 API는 **설치된 LeRobot 버전 문서로 확인**한다(버전마다 바뀜).

| 항목 | 내용 |
|---|---|
| observation.state | 관절 각도 6개 (rad), 그리퍼 포함 |
| observation.images.top | 시뮬레이션 위쪽 카메라 화면 (웹캠 영상 아님) |
| action | 다음 목표 관절 각도 6개 |
| 추가 | source(demo/correction), is_intervention, seed, success |

블록·목표 위치는 시드 목록으로 정하고, 시연용 시드와 평가용 시드는 겹치지 않게 한다.
