# web — 브라우저 손 추적 + 시뮬레이션 연결 + 손으로 로봇 조종

웹캠으로 손을 최대 2개 추적해(MediaPipe Tasks Hand Landmarker, `@mediapipe/tasks-vision` 1.1.1) 21개 점을 그리고,
그중 **조종 손 하나**의 `hand` 메시지(wrist, pinch, pinch_ratio, palm_open, hand_scale)만 파이썬 서버로 최대 30Hz 보낸다.
서버가 보내는 시뮬레이션 화면(top 카메라 JPEG)을 웹캠 옆에 보여준다.
웹캠 영상은 화면에만 보여주고 저장하거나 전송하지 않는다. 서버로 가는 것은 숫자(JSON)뿐이다.

## 조종 손 고르기

- 손은 2개까지 인식하지만 로봇 조종에는 MediaPipe handedness 라벨이 `CONTROL_HANDEDNESS`(`src/hand/config.js`, 기본 `'Right'`)인
  손 하나만 쓴다. 다른 손은 화면에 회색으로만 그리고 서버로 보내지 않는다. 조종 손이 안 보이면 다른 손이 있어도
  `detected: false`를 보낸다(조종이 다른 손으로 넘어가지 않는다).
- 같은 라벨의 손이 둘로 잡히면 신뢰도(score)가 높은 쪽을 쓴다(`src/hand/select.js`).
- **영상을 좌우 뒤집지 않은 원본으로 넣기 때문에 라벨이 실제 손과 반대로 나올 수 있다**(내 오른손이 `Left`). 화면의
  "조종 중인 손" 표시와 노란 굵은 선으로 어느 손인지 직접 확인하고, 반대면 `CONTROL_HANDEDNESS`를 바꾼다.

## 처음 한 번

```bash
cd ~/handover/web
npm install
mkdir -p public/models
curl -fL -o public/models/hand_landmarker.task \
  https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task
```

모델 주소는 `node_modules/@mediapipe/tasks-vision/README.md`에 적힌 것과 같다. `public/models/`와
`public/mediapipe/`(wasm 복사본)는 git에서 제외한다.

## 실행

터미널 두 개를 쓴다.

```bash
# 1) 파이썬 서버 (127.0.0.1:18007, 포트는 server/config.py)
cd ~/handover && MUJOCO_GL=egl server/.venv/bin/python -m server.app

# 2) 웹
cd ~/handover/web && npm run dev
```

- 주소와 포트는 `vite.config.js`에 있다: `127.0.0.1:3007`(내 계정에 배정된 포트), `strictPort: true`라서 포트가 사용 중이면 다른 포트로 넘어가지 않고 오류로 멈춘다.
- `npm run dev`/`npm run build` 전에 `scripts/copy-wasm.mjs`가 wasm을 `public/mediapipe/wasm`으로 복사한다.
- VS Code **Ports**에서 **3007만** **Private**으로 전달하고 노트북 브라우저에서 `http://localhost:3007`을 연다.
  18007(파이썬 서버)은 전달하지 않는다.

## 서버 연결 구조

```
브라우저 ws://localhost:3007/ws ──(Vite 프록시, vite.config.js)──▶ ws://127.0.0.1:18007/ws (FastAPI)
```

- 브라우저 → 서버: `hand`(JSON, 최대 30Hz), `view`(보기 방향, 최대 15Hz, 마지막 값은 반드시 보냄), `height`(키보드 높이),
  `record`/`reset`(녹화 버튼, 누를 때마다 한 번), `ping`(1초마다, 왕복 지연 측정)
- 서버 → 브라우저: 시뮬레이션 화면 JPEG(바이너리, 약 15fps), `state`(0.1초마다, `control` 항목에 로봇 상태, `record` 항목에 녹화 상태),
  `pong`, `error`
- 서버는 연결된 브라우저가 없으면 렌더링을 멈춘다(시뮬레이션 계산은 계속).
- 연결이 끊기면 2초 뒤 자동으로 다시 연결한다. 설정값은 `src/net/config.js`.
- 서버 포트를 바꾸면 `server/config.py`의 `PORT`와 `vite.config.js`의 `SIM_SERVER_PORT`를 같이 바꾼다
  (`src/net/serverPort.test.js`가 둘이 같은지 확인한다).

## 화면에 보이는 것 (로봇 상태, 서버 `state.control`)

- **조종 중인 손:** 라벨(MediaPipe 기준)과 신뢰도, 보이는 손 목록. 조종 손은 노란 굵은 선.
- **집게 높이 막대:** 실제 집게 끝 높이(0~15cm, 파란 막대)와 목표 높이(초록 가로선). 위에서 본 화면만으로는 높이를 알기
  어려워서 렌더링을 더 하지 않고 숫자와 막대로 보여준다.
- **집게 상태(표시등, 버튼 아님):** 엄지·검지를 붙이면 닫힘. 목표 각도와 실제 각도(rad).
- **목표 위치 x, y, z (m), 실제 집게 위치 (m), 둘 사이 거리 (m).**
- **IK 실패 횟수**(실패하면 ctrl을 바꾸지 않고 직전 값 유지), **IK 1회 계산 시간 ms**(마지막/평균/최대, 최근 300개).
- **손 메시지→ctrl ms:** 서버가 hand 메시지를 받은 때부터 ctrl에 반영할 때까지(서버 안 시간). 브라우저→서버는 왕복 지연,
  ctrl 반영 뒤 실제로 움직이기까지(물리 틱 최대 33ms, 모터 응답)는 포함되지 않는다.
- **목표 흔들림:** 최근 1초 동안 목표 위치의 표준편차(mm). 손을 가만히 두고 집게만 열고 닫을 때 값이 크면 손목 기준점이
  집게 동작에 흔들린다는 뜻이다(손바닥 중심으로 바꾸는 것을 다음 작업으로 검토). "필터 후"는 로봇이 받는 목표, "필터 전"은
  필터를 거치기 전 값이다.

## 손 → 로봇 매핑 방식 (상대 이동 = 기본)

서버 `server/config.py`의 `MAPPING_MODE`로 고른다(바꾸면 서버를 다시 띄운다).

- **`"relative"`(기본, 클러치):** 손이 3프레임 연속 보이면 그 순간의 손 위치(3프레임 평균)가 **기준점**이 되고, 이후에는 "손이
  움직인 양 × 이득"만큼 로봇 목표가 움직인다. 손이 화면 밖으로 나가면 로봇은 그 자리에서 멈추고, 다시 들어와 3프레임 연속
  보이면 그 순간이 새 기준점이 된다(마우스를 들어 옮기는 것과 같다). 처음 조종할 때 로봇 쪽 기준은 작업 상자 중심이다.
  방향은 **현재 보기 기준**: 손을 오른쪽으로 → 화면에서도 오른쪽, 손을 위로 → 화면에서 안쪽(멀어지는 방향). 보기를 돌려도
  이미 간 위치는 그대로이고 이후 손 움직임에만 새 방향이 적용된다.
- **`"absolute"`:** 손 위치 = 로봇 위치(2-2 동작 그대로). 방향은 월드 고정(위에서 본 화면 기준)이라 보기를 돌리면 어긋나 보인다.

**이득을 바꾸는 곳: `server/config.py`의 `RELATIVE_GAIN_XY_M_PER_WIDTH`(수평)와 `RELATIVE_GAIN_Z_M_PER_SCALE`(높이, 아래 참고).**
기본은 수평 약 1.03 m/영상 너비(손이 화면 너비의 35% 움직이면 상자의 가장 긴 변 0.36 m, 64 px에 약 10.3 cm). 값을 올리면 더 민감하다.
숫자를 직접 적어도 된다. 높이 이득(-0.875 m/hand_scale)은 `Z_FROM_HAND_SCALE = True`일 때만 쓰인다. 기본은 높이를 키보드로 정한다.

## 높이는 키보드로 (2-5)

손은 좌우·앞뒤와 집게 열고 닫기만 맡는다. **집게 높이는 키보드**로 바꾼다.

| 키 | 동작 |
|---|---|
| ↓ 또는 S (누르는 동안) | 내려감 |
| ↑ 또는 W (누르는 동안) | 올라감 |
| 둘 다 | 정지 |
| Shift를 같이 | 천천히(미세 조정) |

- 키는 물리 키 위치(`event.code`)로 읽어서 한글 입력기가 켜져 있어도 W/S가 동작한다. 방향키가 페이지를 스크롤하지 않는다.
  입력창(`input`, `textarea`)에 포커스가 있을 때와 Ctrl/Cmd/Alt와 같이 누른 키(Ctrl+S 등)는 무시한다.
- 키 상태가 바뀔 때 `{"type":"height","dir":-1|0|1,"slow":true|false}`를 보내고, 누르고 있는 동안 20Hz(`src/net/config.js`의
  `HEIGHT_REPEAT_HZ`)로 되풀이한다. 창이나 탭이 포커스를 잃으면(blur, 탭 숨김) `dir 0`을 보내고 키 상태를 비운다. 연결이 끊기면
  보낼 수 없으므로 키 상태만 비우고, 재연결 직후 `dir 0`을 보낸다.
- 서버는 마지막 `height` 메시지를 받은 지 0.3초가 지나면 키가 떼어진 것으로 본다(브라우저가 죽어도 로봇이 계속 내려가지 않는다.
  그사이 움직이는 거리는 최대 0.08 m/s × 0.3초 = 2.4 cm).
- **손으로 조종을 시작한 뒤부터 동작한다.** 조종이 한 번도 시작되지 않았을 때(목표가 없을 때) 누른 키는 무시한다(키를 잘못 눌러 로봇이
  갑자기 움직이는 사고를 막으려고). 손이 안 보이는 동안에도 높이는 바뀐다.
- 키보드로 바뀐 높이도 변화량 제한과 IK를 거치므로 로봇이 튀지 않는다. 작업 상자 높이(0.015~0.12 m) 밖으로는 안 나간다.

**높이 속도를 바꾸는 곳: `server/config.py`의 `HEIGHT_SPEED_M_S`(기본 0.08 m/s)와 `HEIGHT_SLOW_SPEED_M_S`(Shift, 기본 0.02 m/s).**
상자 맨 위에서 맨 아래까지 걸리는 시간 = 0.105 m ÷ 속도: 0.08 → 1.31초, 0.05 → 2.1초, 0.04 → 2.6초, 0.03 → 3.5초, 천천히 0.02 → 5.25초.
블록을 집으려고 내릴 때 너무 빠르면 `HEIGHT_SPEED_M_S`를 줄인다(서버를 다시 띄워야 반영된다).

`Z_FROM_HAND_SCALE = True`로 켜면 손 크기로 정한 높이(2-4 동작)에 키보드 높이가 더해진다. 기본은 `False`(손 크기는 높이에 영향 없음).

화면의 "키보드 조작" 상자: 눌린 키(↑, ↓, Shift)가 켜지고, 서버가 확인한 상태("내려가는 중", "상자 맨 위", "상자 맨 아래", 조종 시작 전에는
"손으로 조종을 시작한 뒤부터 동작합니다")가 나온다. 키캡은 누르는 버튼이 아니라 표시다.

**블록 근처에서 내릴 때:** 블록(한 변 3 cm, 윗면 높이 3 cm) 바로 위에서 집게를 내리면 열린 집게가 블록 윗면에 얹혀 블록을 밀 수 있다.
먼저 좌우·앞뒤로 집게가 블록 양옆에 오게 맞춘 뒤 내린다.

화면 안내(웹캠 화면):

- **하늘색 십자 = 기준점, 주황 점 = 지금 손목, 점선 = 움직인 양**(상대 모드, 조종 중일 때).
- 손(21개 점 전체)이 영상 가장자리 10% 안쪽에 들어오면 웹캠 테두리가 **빨개지고** "화면 가장자리: 손을 화면 밖으로 뺐다가
  중앙에서 다시 넣으면 이어서 움직여요"가 나온다(`src/hand/config.js`의 `EDGE_MARGIN`).
- 조종 상태 문구: "손 기준점 잡는 중 (n/3)", "손을 따라가는 중", "손 안 보임 → 정지 (중앙에서 다시 넣으세요)".

시뮬레이션 화면 오른쪽 위 **나침반**: "앞"(주황) = 로봇 앞쪽(+x)이 지금 보기에서 가리키는 방향(보기를 돌리면 같이 돈다, 비스듬히
볼수록 짧아 보인다). "손 위", "손 오른쪽"(하늘색)은 손을 그 방향으로 움직이면 로봇이 가는 방향이다. 상대 모드에서는 늘 화면
위/오른쪽이고, 절대 모드에서는 월드 고정이라 보기를 돌리면 같이 돈다.

## 보기 방향 (시뮬레이션 화면 돌리기)

- 서버는 고정 top 카메라 대신 자유 카메라(`mujoco.MjvCamera`)로 그린다. 방위각, 고도각, 거리를 바꿀 수 있고
  바라보는 점은 작업 상자 중심 근처로 고정이다. scene.xml의 top 카메라는 그대로 있어서 `server/config.py`의
  `CAMERA = "top"`으로 바꾸면 예전 화면이 된다(3단계 학습 이미지용).
- **마우스:** 화면 위에서 끌면 좌우 = 방위각, 상하 = 고도각. 휠 = 거리. 감도와 부호는 `src/view/config.js`.
- **프리셋:** "위에서"(예전 top과 같은 방향), "옆에서"(로봇 앞쪽 +x가 화면 오른쪽, 집게 높이가 보임),
  "비스듬히 (기본)". 값의 원본은 `server/config.py`의 `VIEW_PRESETS`이고 `src/view/serverView.test.js`가 같은지 확인한다.
- `view` 메시지는 최대 15Hz로 보낸다(`src/net/throttle.js`). 마지막 값은 반드시 보낸다.
- 보기 방향은 서버에 하나뿐이다. 브라우저를 여러 개 열어 두면 마지막에 바꾼 값이 모두에게 적용된다.
- **손 방향은 현재 보기 기준이다**(상대 모드). 절대 모드에서는 월드 고정이라 보기를 돌리면 어긋나 보인다(화면에 그렇게 표시된다).
- 화면 아래 범례: 빨강 = 블록, 초록 = 목표. 지금 보기 값(방위각, 고도각, 거리)을 숫자로 보여준다.

## 시연 녹화 상자 (3-2)

시뮬레이션 화면 아래의 "시연 녹화" 상자. 서버 `state.record`를 보여 주고 버튼을 누르면 서버로 명령을 보낸다. 저장 형식, 시드, 성공 판정,
시연 20개를 찍는 절차와 요령은 [docs/08-recording.md](../docs/08-recording.md). 웹캠 영상이나 이미지는 저장하지 않는다(서버가 상태 숫자만 저장).

| 버튼 | 보내는 메시지 | 눌릴 수 있을 때 |
|---|---|---|
| 블록 리셋(다음 시드) | `{"type":"reset"}` | 녹화 중이 아니고 리셋 중이 아닐 때 |
| 녹화 시작 | `{"type":"record","action":"start"}` | **리셋 직후**(블록이 시드 위치에 있을 때)만 |
| 끝: 성공 / 끝: 실패 | `{"type":"record","action":"stop_success"}` / `"stop_fail"` | 녹화 중 |
| 취소(버리기) | `{"type":"record","action":"discard"}` | 녹화 중. 저장하지 않는다 |
| 마지막 에피소드 삭제 | `{"type":"record","action":"delete_last","episode":N}` | 저장된 것이 있을 때. **두 번 눌러야** 지운다(3초 안) |

- 버튼이 꺼져 있는 이유는 버튼에 마우스를 올리면(title) 나온다. 눌릴 수 있는지는 서버가 같은 규칙으로 다시 검사한다(화면은 안내).
  서버가 거절하면(예: 녹화 중 리셋) 상자의 안내 줄에 이유가 나온다. 잘못된 메시지가 아니므로 "서버가 거부한 메시지" 숫자는 늘지 않는다.
- 표시: 녹화 상태 문구, **경과 시간(최대 60초)**, 기록한 틱 수, **지금 시드/다음 시드**, 저장된 성공/실패 수, **정지 구간 비율**(로봇이
  거의 안 움직인 샘플의 비율과 가장 긴 정지. 50% 이상이거나 3초 이상이면 노란 경고, 기준은 `src/record/config.js`), 마지막 저장,
  틱 간격(최근 평균/최대 ms), **"성공 조건 달성"**(초록 띠, 최종 성공은 내가 누른 버튼이 정한다).
- 저장이 실패하면(디스크 가득 등) 빨간 안내가 뜨고 그 에피소드는 성공/실패 수에 들어가지 않는다.
- **키보드 높이(↑↓, W/S)와 충돌하지 않는다:** 높이 키는 window에서 받으므로 버튼에 포커스가 있어도 동작한다
  (`src/input/heightKeysButtonFocus.test.js`). 버튼은 클릭 직후 포커스를 풀어서 Enter/Space로 다시 눌리지 않는다.
- 로직은 `src/record/view.js`(버튼 활성 조건, 메시지 만들기, 문구), `src/record/confirm.js`(삭제 2단계 확인)에 있고 vitest로 확인한다.
  이 환경에는 DOM 테스트 도구가 없어서 실제 클릭과 모양은 브라우저에서 직접 확인한다.

## 브라우저에서 확인하기

1. 서버와 웹을 띄우고(위 실행) `http://localhost:3007`을 연다. 시뮬레이션 화면이 나오고 "서버에 연결되지 않음"이 아닌지 본다.
2. **카메라 켜기** → 양손을 보여준다. 점이 둘 다 그려지고 한 손만 노란 선이다. "조종 중인 손" 라벨이 실제와 반대면
   `CONTROL_HANDEDNESS`를 바꾼다. 조종하지 않는 손을 흔들어도 로봇이 움직이지 않아야 한다.
3. 조종 손을 처음 보이면 "조종 손 확인 중 (n/3프레임 연속)" 뒤 "손을 따라가는 중"이 된다. 로봇이 홈 자세에서 튀지 않고
   부드럽게 손 위치로 온다.
4. 손을 오른쪽/위로 → 시뮬레이션 화면 속 집게도 오른쪽/위로. 손을 카메라에 가까이 → 집게 높이 막대가 줄어든다.
5. 손을 화면 밖으로 → "마지막 목표에서 멈춤", 로봇이 그 자리에 선다.
6. 엄지와 검지를 붙이면 집게가 "닫힘", 펴면 "열림". 반쯤 붙인 채로는 직전 상태가 유지된다.
7. 목표와 집게 거리는 가만히 있을 때 몇 mm, 빠르게 움직일 때는 더 커진다. IK 실패 횟수는 보통 0이다.

## 외부 전송 차단

`@mediapipe/tasks-vision` 1.1.1은 HandLandmarker를 만들면 사용 통계를 60초마다
`https://odml.pa.googleapis.com/v1/log`로 보내는 코드가 들어 있다(`vision_bundle.mjs`). 끄는 옵션이 없어서
`index.html`에 `Content-Security-Policy: connect-src 'self'`를 넣어 브라우저가 같은 주소(localhost) 밖으로
연결하지 못하게 막았다. 서버 WebSocket은 같은 주소(`localhost:3007/ws`)로 붙고 Vite가 파이썬 서버로 넘겨주므로
CSP는 바꾸지 않는다.
